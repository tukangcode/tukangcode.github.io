? Versi 30 Detik

Function calling = agent bilang "saya mau pakai alat ini" dalam bahasa yang komputer bisa langsung eksekusi. Bukan kalimat manusia, tapi kode.

Tool use = proses lengkapnya: pilih alat → pakai → baca hasil → mikir lagi. Dua-duanya istilah yang sama, cuma beda sudut pandang.

💡 Bayangin kamu suruh montir "perbaiki ban". Montir nggak cuma bilang "oke" — dia ambil kunci, buka ban, tambal, pasang balik, tes. Tool use itu gerakan montir itu. Otaknya cuma tahu "harus tambal", tapi tangannya yang kerja.

1 Analogi Sederhana

Bayangin kamu di dapur. Kamu mau masak mie. Otakmu bilang: "rebus air dulu". Tapi otakmu nggak bisa nyalain kompor sendiri — kamu harus pakai tangan untuk ambil panci, isi air, nyalain kompor.

Nah, di agent:

  • Otak = model AI — dia tahu apa yang harus dikerjain, tapi nggak bisa ngapa-ngapain sendiri.
  • Tangan = tool / function — alat yang bikin agent bisa "pegang" sesuatu: baca file, buka web, jalanin kode.
  • Resep = instruksi kamu — kalau nggak jelas, hasilnya nggak jelas.

2 Alurnya Gimana?

Lihat gambar di bawah. Agent nggak sekali jawab — dia putar balik ke otaknya setelah pakai tool, baca hasilnya, terus mikir lagi.

Tiap panah = satu langkah. Agent bisa muter ini berkali-kali sampai tugasnya beneran selesai.

3 Studi Kasus Nyata: deepseek-flash vs GLM 5.3

Ini bukan teori — ini kejadian beneran pas tutorial Hermes di halaman ini dibikun.

⚠️ Apa yang terjadi?
deepseek-flash dipakai buat nulis kode HTML. Dia "berhasil" bikin semua halaman, semua link, semua struktur. Tapi waktu dibuka: link nggak nyambung — buka malah muncul directory listing, bukan halaman yang dituju.

Kenapa? deepseek-flash nulis href="../apa-itu-agent/index.html" — path folder tanpa index.html. Di web server ini jalan. Tapi dibuka lewat file:/// di Windows, browser buka directory listing, bukan halaman HTML.

Model yang lebih kuat (GLM 5.3) dipanggil buat fix. Dia langsung tahu: tulis href="../apa-itu-agent/index.html" — eksplisit, jalan di mana aja.

Pelajaran: model lemah nggak akan bilang "saya nggak yakin". Dia bikin hasil yang kelihatannya benar — struktur HTML bagus, kodenya rapi, tapi ada bug halus yang nggak kelihatan sampai dibuka beneran. Ini yang bahaya.

! Tanda Model Lemah saat Pakai Tool

1. Hasilnya "kelihatannya benar" tapi rusak waktu dijalankan

HTML bagus, kode rapi, struktur bener — tapi ada detail halus yang salah: path file, format argument, nama function yang nggak ada. Model nggak tahu dia salah karena dia nggak menjalankan hasilnya.

2. Panggil tool tapi argumennya nggak lengkap / salah format

Contoh: manggil read_file() tapi path-nya cuma nama folder, bukan nama file lengkap. Atau web_search() tapi query-nya kosong. Tool-nya bener, tapi "bahan" yang dikasih salah.

3. Pilih tool yang nggak relevan

Disuruh "baca file config" tapi yang dipanggil web_search(). Atau disuruh "cari di internet" tapi yang dipanggil read_file(). Otaknya bingung milih alat.

4. Nggak baca hasil tool — langsung jawab ngasal

Tool sudah jalan, sudah kasih data, tapi model nggak baca datanya dan malah jawab pakai "pengetahuan" sendiri yang bisa jadi salah. Hasil tool dibuang sia-sia.

5. Muter di tempat — panggil tool yang sama berkali-kali

Tool error, model coba lagi dengan argumen yang sama persis, error lagi, coba lagi... nggak sadar harus ganti cara. Ini tanda model nggak bisa "mikir keluar dari kotak".

✓ Cara Aman Pakai Tool dengan Model Lemah

1
Selalu verifikasi hasil

Jangan percaya output begitu saja. Buka file yang dibikin, klik link-nya, jalanin kodenya. Kalau rusak, pakai model yang lebih kuat buat fix.

2
Kasih instruksi yang sangat spesifik

Bukan "bikin link ke halaman agent" tapi "tulis href lengkap ke agentic/apa-itu-agent/index.html, jangan cuma nama folder". Model lemah butuh instruksi yang sangat jelas.

3
Pisah tugas jadi langkah kecil

Jangan sekali minta "bikin web lengkap". Pecah jadi: 1) bikin struktur, 2) isi konten, 3) fix link. Tiap langkah bisa dicek sendiri.

4
Pakai model yang tepat untuk tugas yang tepat

Model kecil buat tugas sederhana (nulis teks, jawab pertanyaan). Model besar buat tugas yang butuh tool use kompleks (ngoding, multi-step, file ops). Jangan maksa model kecil bikin sistem kompleks.

💡 Aturan praktis: kalau hasilnya penting dan butuh presisi, pakai model yang lebih kuat. Kalau cuma butuh draft cepat, model kecil boleh — tapi tetap cek hasilnya.
